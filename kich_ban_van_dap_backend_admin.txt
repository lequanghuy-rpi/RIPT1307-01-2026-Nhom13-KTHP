# KỊCH BẢN TRẢ LỜI VẤN ĐÁP ĐỒ ÁN (PHẦN BACKEND & ADMIN)

Chào bạn, đây là tài liệu được biên soạn để giúp bạn tự tin bảo vệ đồ án đối với phần việc mà bạn đảm nhận: **Xây dựng toàn bộ Backend và Trang quản trị (Admin)**.

---

## PHẦN 1: TỔNG QUAN CÔNG NGHỆ SỬ DỤNG (TECHNOLOGY STACK)

Khi thầy cô hỏi: *"Em đã dùng những công nghệ gì để xây dựng phần Backend và trang Admin?"*

**Trả lời:**
- **Về Backend:** Em sử dụng **Node.js** với framework **Express.js** để xây dựng các RESTful API. Hệ thống được viết bằng **TypeScript** để đảm bảo tính chặt chẽ của kiểu dữ liệu. Để tương tác với cơ sở dữ liệu (Database), em sử dụng **Prisma ORM** kết nối với hệ quản trị cơ sở dữ liệu (MySQL/TiDB). Xác thực người dùng và phân quyền được xử lý thông qua **JWT (JSON Web Token)**.
- **Về Frontend (Trang Admin):** Em sử dụng **React.js** kết hợp với framework **UmiJS** để quản lý routing và state tổng thể. Giao diện quản trị viên (UI) được xây dựng hoàn toàn bằng thư viện component **Ant Design (antd)** để đảm bảo tính đồng bộ, chuyên nghiệp và tối ưu thời gian phát triển. Để vẽ biểu đồ thống kê, em dùng thư viện `@ant-design/charts`.

## PHẦN 2: CẤU TRÚC THƯ MỤC VÀ CÁC FILE QUAN TRỌNG

Khi thầy cô hỏi: *"Em hãy chỉ ra những file code chính do em viết và chức năng của chúng là gì?"*

### 1. Phía Backend (`/backend/src/`)
- **`prisma/schema.prisma`**: Nơi định nghĩa toàn bộ cấu trúc các bảng trong Database 
(Models: User, Tournament, Registration, Match, Notification...). Đây là trái tim của hệ thống dữ liệu.
- **`src/routes/`**: Định nghĩa đường dẫn API (Endpoints). Các file như `tournament.routes.ts`, `registration.routes.ts` sẽ định tuyến các request từ Frontend (GET, POST, PUT, DELETE) đến đúng hàm xử lý.
- **`src/controllers/`**: Chứa logic xử lý chính. 
Ví dụ `tournament.controller.ts`, `stats.controller.ts`, `registration.controller.ts`. 
Khi nhận request, controller sẽ lấy dữ liệu, dùng Prisma query xuống DB, tính toán logic và trả về JSON cho Frontend.
- **`src/middlewares/`**: Đặc biệt là `auth.middleware.ts`. File này đóng vai trò "người bảo vệ", 
nó chặn các request gửi lên, kiểm tra xem có chứa token JWT hợp lệ không, 
và user đó có phải là `ADMIN` hay không thì mới cho đi tiếp vào Controller.

### 2. Phía Frontend Admin (`/frontend/src/pages/Admin/`)
- **`tournaments/index.tsx`**: Trang Quản lý Giải đấu. Nơi Admin có thể xem danh sách, 
Thêm/Sửa/Xóa giải đấu. Dùng component `<Table>`, `<Modal>`, `<Form>` của Ant Design.
- **`registrations/index.tsx`**: Trang Quản lý Đơn đăng ký. Nơi Admin xem thông tin đội, duyệt hoặc từ chối đơn. 
Có tích hợp tính năng xuất danh sách ra file Excel bằng thư viện `xlsx`.
- **`statistics/index.tsx`**: Trang Thống kê tổng quan. Gọi dữ liệu để hiển thị tổng số giải đấu, 
biểu đồ đường (số lượng đăng ký theo ngày) và biểu đồ tròn (tỷ lệ duyệt đơn).
- **`src/services/`**: Các file như `adminTournament.service.ts`, `adminStatistics.service.ts`. 
Chứa các hàm dùng để gọi API (fetch data) từ Frontend lên Backend.

## PHẦN 3: GIẢI THÍCH LUỒNG HOẠT ĐỘNG (HOW IT WORKS)

Thầy cô thường hay yêu cầu: *"Em hãy giải thích luồng chạy của code từ lúc thao tác trên màn hình cho đến khi lưu vào Database?"*

### Câu hỏi 1: Cơ chế Bảo mật và Phân quyền Admin hoạt động ra sao?
**Trả lời:** 
"Hệ thống của em sử dụng JWT. Khi Admin đăng nhập thành công, Backend sẽ tạo ra một chuỗi JWT Token mã hóa thông tin User (gồm ID và Role='ADMIN') và gửi về Frontend lưu lại.
Bên trang Admin (UmiJS), em cấu hình bảo vệ route: nếu role không phải ADMIN thì sẽ bị đẩy ra ngoài.
Khi thao tác, mỗi request từ Frontend gửi lên Backend đều đính kèm Token này ở Header `Authorization`. Backend sẽ dùng `auth.middleware` để giải mã, nếu đúng là Token chuẩn và Role='ADMIN' thì mới cho phép thực thi lệnh (ví dụ xóa giải đấu), nếu không sẽ trả về lỗi 403 Forbidden."

### Câu hỏi 2: Giải thích luồng Thêm/Sửa một giải đấu diễn ra thế nào?
**Trả lời:**
1. Trên giao diện `tournaments/index.tsx`, khi Admin nhấn "Lưu thay đổi", component `<Form>` của Ant Design sẽ tự động chạy hàm `validateFields()` để kiểm tra dữ liệu đầu vào (ví dụ: ngày kết thúc phải sau ngày bắt đầu, số đội phải là số chẵn).
2. Nếu dữ liệu hợp lệ, Frontend gọi hàm từ thư mục `services`, gửi một request `POST` (nếu tạo mới) hoặc `PUT` (nếu cập nhật) lên Backend.
3. Ở Backend, `tournament.routes.ts` sẽ bắt request này, đưa qua middleware xác thực Admin, rồi chuyển cho `tournament.controller.ts`.
4. Tại Controller, em sử dụng các câu lệnh của Prisma như `prisma.tournament.create()` hoặc `prisma.tournament.update()` để lưu dữ liệu xuống Database.
5. Sau khi lưu thành công, Backend trả về response `success: true`. Frontend nhận được, tự động đóng Modal (cửa sổ popup), hiện thông báo "Cập nhật thành công" (dùng `message` của antd) và tự động gọi lại hàm `fetchTournaments()` để tải lại bảng dữ liệu mới nhất.

### Câu hỏi 3: Trang Thống kê (Statistics) hoạt động thế nào để không bị chậm?
**Trả lời:** 
"Trang thống kê cần lấy nhiều loại dữ liệu: tổng số liệu, biểu đồ đường, biểu đồ tròn, và top giải đấu.
Thay vì gọi từng API chờ xong mới gọi API tiếp theo (sẽ rất chậm), trong file `statistics/index.tsx`, em sử dụng `Promise.all([getOverview(), getRegistrationsByDate(), ...])`. 
Cách này giúp Frontend gửi nhiều request lấy dữ liệu cùng một lúc (bất đồng bộ song song). Ở Backend, các Controller tương ứng sẽ dùng Prisma để đếm (`prisma.tournament.count()`) hoặc dùng câu lệnh `groupBy` để nhóm dữ liệu. Khi tất cả hoàn tất, Frontend sẽ render dữ liệu ra các component biểu đồ của thư viện Ant Design Charts."

## PHẦN 4: NHỮNG ĐIỂM NỔI BẬT CỦA PHẦN BẠN LÀM (ĐỂ "KHOE" VỚI THẦY CÔ)

Nếu được hỏi *"Đâu là điểm em tâm đắc nhất ở phần việc của mình?"*, bạn có thể tự tin nêu ra:
1. **Thiết kế Database chuẩn mực:** Sử dụng Prisma ORM giúp việc thao tác với quan hệ giữa các bảng (Relations: Tournament -> Registration -> Users) cực kỳ chặt chẽ và an toàn về mặt kiểu dữ liệu (Type-safe).
2. **Tối ưu hóa UI/UX cho trang Quản trị:** Em tận dụng triệt để sức mạnh của Ant Design (như Skeleton loading, Popconfirm chống xóa nhầm dữ liệu, Form validation chi tiết) để trang Admin có trải nghiệm mượt mà không kém các sản phẩm thực tế.
3. **Tính năng Xuất Excel:** Không chỉ thao tác trên web, em còn tích hợp thư viện `xlsx` để cho phép Admin tải danh sách đơn đăng ký thành file Excel, rất tiện dụng trong thực tế quản lý giải đấu.
4. **Viết API hiệu quả:** Tách biệt rõ ràng Route, Controller, Service giúp code dễ bảo trì, dễ đọc. Xử lý tốt các ngoại lệ (Try/Catch) để trả về thông báo lỗi rõ ràng cho người dùng thay vì làm sập server.
